# Repository instructions

This is a standalone Kotlin/JVM library. Read [docs/agents/index.md](docs/agents/index.md) for integration; do not scrape the HTML site. [IMPORT.md](IMPORT.md) is the generated, authoritative confirmed installation record.

- Preserve public API behavior. Document surprising behavior; do not silently change it during documentation work.
- Canonical guides live in `docs/agents/`. Human HTML and raw Markdown mirrors are generated by the pinned shared `android-repo-docs` Astro backend; edit sources, not generated pages.
- Runnable documentation lives in `src/test/java/com/apexfission/android/math/examples/DocumentationExamplesTest.kt`. Quickstart code is extracted from its marked region.
- Verify with `./gradlew test runExamples verifyImportDocs`, `sh ./setup.sh --version && node --test tests/*.test.mjs`, and `sh ./docs.sh build --check && node --test sites/tests/*.test.mjs`. JDK 17 and Node 24 are required; no Android SDK.
- Never hand-edit IMPORT.md. Preserve legacy `docs/release.json` evidence and the confirmed per-destination pointers/history under `docs/releases/`. Central and JitPack track independent source/version identities; only verified public artifacts advance installation docs. See [release runbook](docs/releases.md).
- Use the pinned `setup.sh`/`setup.bat` CLI for release policy, verification and generated workflows. Publishing remains manual; docs-only retries must never allocate a release or upload a package.
- No UI screenshots are needed for this numerical library. See [documentation maintenance](docs/documentation.md) for the visual and publication policy.

## Versioned and translated documentation

Canonical English remains in `docs/agents/`; Spanish lives in `docs/es/`. Preserve code fences, identifiers, numeric examples and documented edge cases. Record the canonical English SHA256 per reviewed translation; missing/stale translations fall back visibly to English from the same documentation revision.

Preserve each release’s immutable source separately from its documentation revision. The 0.1.0 manual uses the later retained documentation commit after verifying the runtime sources are identical. Example source added after release belongs to that documentation revision. Never pin an unmerged local commit as a durable historical manual. Build snapshots as data using the current renderer; do not execute old scripts. Keep version/language switches, scoped links and raw Markdown consistent. Read `docs/documentation.md` before changing the archive or site.

## Shared tooling boundary

The setup CLI owns JVM JAR publication verification, release identity, journals,
reconciliation and generated GitHub workflows. The documentation CLI owns
installation rendering, archives and Astro. Their independent pins are deliberate;
see `docs/releases.md` for the temporary setup parser correction and the historical
JitPack recovery boundary. Do not restore repository-local Python tooling.

Initialize the setup cache before consumer contract tests: `sh ./setup.sh --version`
(or `setup.bat --version` on Windows). Tests under `tests/` call the real CLI on
isolated local fixtures. Source/output tests remain under `sites/tests/`.

Preserve existing publication coordinates, Java 11 bytecode, Kotlin/Gradle pins,
POM metadata and Markdown-only documentation classifier inclusion. Do not apply
the Android-only Gradle publication plugin to this JVM root project. Never trigger
publication or reconcile live attempts as part of documentation/tooling checks.
